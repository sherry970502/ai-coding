# 用户反馈归纳（2026-10 · 来源：网龙AI编程-用户体验反馈收集表）

两部分来源：Sheet1 为平台体验反馈 34 条（黄雨晴、吴家辉、严超锦、WP、JZJ、ZL、ZXM、WYF、乔凡林），Sheet2 为一个生成出来的游戏成品的 13 条 UI 缺陷（灵犀，10.8）。合计 47 条，归纳为 9 类需求。

## 一、按主题归纳

### 1. 过程透明：进度与预估时长（7 条，最高频）
- 迭代/制作等待太久、时长未知、过程无反馈（ZL、ZXM×2、WYF、乔凡林）
- 建议给进度条、预估等待时间（ZXM、乔凡林）

**v0.3 响应**：制作页显示预估剩余时间（按本机最近几次实际耗时估算）+ 阶段进度；快速修改遮罩同样显示预估时间。

### 2. 成本透明：token / 积分（5 条）
- 每项需求希望事前知道消耗（乔凡林）
- 构建失败也计费，体验很怪（吴家辉）→ 处理记录：失败不扣积分 + 计费规则入口
- 改几个字也走完整构建、双倍消耗（吴家辉）；补充需求导致大改、消耗大（黄雨晴）

**v0.3 响应**：积分账本（顶栏余额 + 计费规则 + 消耗明细）；所有操作事前显示预估消耗；失败记 0 消耗流水、明细中可见「失败 · 未扣除」。

### 3. 小改不该大动（3 条）
- 小修改走完整构建（吴家辉）、AI 大幅修改消耗大（黄雨晴）、颜色/风格调整反复解读出错（ZXM）

**v0.3 响应**：点选改文字免费（原有）；新增「修改清单」——多处小改攒成一次构建、按一次计费；工程师提示词加「严格按字面修改、不顺手重构、多处修改逐条执行」约束。

### 4. 失败可诊断、可恢复（8 条）
- 生成失败无原因、只能盲目重试（吴家辉、乔凡林）；界面空白反复重试（严超锦×2）；中断后无法继续、重复消耗（ZXM、严超锦）；失败后输入框内容丢失（乔凡林）；视觉设计生成 bug（WP）

**v0.3 响应**：失败弹层显示原因、保留完整修改要求、一键原样重试、不扣积分。（真正的断点续作需后端支持，见 v0.4 方向。）

### 5. 版本回退（1 条）
- 迭代不满意无法回退（ZL）——功能其实已有但不可见性差

**v0.3 响应**：历史菜单每个旧版本加「⟲ 恢复」；查看旧版本时顶部横幅提示并提供「恢复这个版本 / 回到最新」。

### 6. 需求输入增强（4 条）
- 希望提供竞品作参考（黄雨晴）；上传 PDF/Word/TXT/图片生成应用（WP）；上下文读取不准、反复输入（JZJ）；批量需求无法逐条确认（ZXM）

**v0.3 响应**：对话支持 📎 附件（txt/md/csv/json 直接读入；PDF/Word/图片诚实提示"支持中"）；PM 提示词支持参考材料与竞品、批量需求逐条编号复述确认。

### 7. 平台能力引导（3 条）
- 未引导数据存储、产出单机版有丢数据隐患（严超锦）；同步给别人看不到数据（严超锦）→ 处理记录：云端数据；能力词出现在对话里但没有自动勾选、发布页前不知道是什么（吴家辉）→ 处理记录：自动开启并写明原因

**v0.3 响应**：PM 方案新增 recommendedServices（能力 + 大白话原因），确认方案时自动开通并提示；方案卡能力行显示「方案推荐」徽标与原因。

### 8. 成品质量（14 条：Sheet2 全部 13 条 + 统计图异常）
- 文字重叠/遮挡、点不开的按钮、空红点、地图/图表显示异常、未全屏、乱码等（灵犀、ZL、乔凡林）

**v0.3 响应**：新增「🩺 产品体检」——验收工程师过一遍成品，输出大白话问题清单（严重程度 + 位置表现），支持单条修复或一键修复全部（合并为一次计费）。工程师/QA 提示词均覆盖 Sheet2 的问题类型。

### 9. 发布与运维（4 条）
- 没有下线/暂停入口，只能删项目（吴家辉）→ 处理记录：暂停访问
- 小程序交付无法预览（黄雨晴）→ 备注确认无法解决（微信机制）
- 生成安装包 Failed to fetch（乔凡林）→ 归入失败可恢复
- 标准版希望可选高阶模型（严超锦）→ 设置中已有模型档位，计费规则中写明消耗差异

**v0.3 响应**：发布页新增「⏸ 暂停访问 / ▶ 恢复访问」，项目、数据、链接保留。

## 二、本版不做（及原因）
- **小程序真机预览**：微信审核机制限制，平台侧无解（反馈表备注已确认）。
- **断点续作（从中断处继续生成）**：需要后端保存生成现场，列入 v0.4；v0.3 先做到"失败保留要求 + 一键重试 + 不扣费"。
- **PDF/Word/图片识别**：需要文档解析服务，先支持纯文本格式并诚实提示。
- **后端逻辑 bug 的定向修复链路**（吴家辉）：当前产品形态是单文件应用，"体检 + 定向修复指令"可覆盖大部分；真实前后端分离架构后再设计。
