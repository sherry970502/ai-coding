# 微信小程序出口 · 打通方案说明

> 原型中「发布上线」阶段已提供小程序渠道入口与用户侧四步说明弹窗。
> 本文说明技术上如何真正打通，供研发评估排期。

## 用户侧流程（原型已呈现）

1. **准备小程序账号**：用户在微信公众平台注册小程序、完成主体认证，拿到 AppID。
2. **绑定到造物工坊**：填 AppID + 扫码授权（第三方平台代开发授权）。
3. **自动生成小程序版**：平台把 Web 产品转换成小程序代码包，用户零操作。
4. **平台代提审**：代上传、提交审核，进度实时显示；必须本人操作的环节（类目资质、备案）给图文代办指引。

## 技术路径（推荐顺序）

### 路径 A：web-view 壳（首选，最快打通）
- 小程序只含一个 `<web-view>` 组件，指向已发布的 H5 链接（Phase 1 的托管产物）。
- 前提：域名需在小程序后台配置业务域名（已备案 + 校验文件），因此**托管域名的 ICP 备案是前置依赖**。
- 限制：个人主体小程序不支持 web-view（需企业主体）；部分微信能力（支付、分享卡片自定义）受限。
- 结论：一套底座零转换成本，先覆盖企业主体用户。

### 路径 B：编译转换（远期增强）
- 把生成的单文件 HTML 底座迁到 Taro/uni-app 之类的跨端框架，产出原生小程序包，解除 web-view 限制、支持个人主体。
- 代价大：影响代码生成器的产出契约，建议在平台 SDK 层稳定之后再评估。

## 平台侧要做的事

1. **注册微信第三方平台**（开放平台企业资质），获得代开发权限：用户扫码授权后，平台可代调用小程序 API。
2. **代码上传与提审自动化**：`miniprogram-ci`（微信官方 CLI）完成上传、预览二维码、提审、发布；平台侧做任务队列 + 状态回调。
3. **代办清单引擎**：把"注册 → 认证 → 授权 → 配域名 → 提审 → 发布"建模成任务流，每步区分「平台代办 / 需用户操作（给图文指引）」，进度在发布面板实时展示。
4. **审核驳回处理**：驳回原因转译成大白话 + 一键修复建议（常见：类目不符、缺资质、页面空白）。

## 关键依赖与风险

- **ICP 备案**：web-view 业务域名必须备案，是国内链路的最长前置（首次约 1~3 周）。建议托管域名提前统一备案。
- **主体门槛**：个人主体不能用 web-view，需在绑定环节检测主体类型并引导。
- **审核周期**：1~7 天不可控，产品上要管理预期（进度条 + 通知）。
- **类目资质**：部分类目（医疗、教育等）需要资质，PM 对话阶段可提前提示。

## 与原型的衔接

- 渠道卡片状态机已预留：`PublishState.channels.mini`（idle/working/done），落地时接入真实任务状态即可。
- 「我有兴趣，通知我」按钮可先接一个意向收集接口，用于排期决策。
