第三节

功能详解与验收标准

01积分账本与计费透明

交互顶栏常驻「⚡ 余额」；抽屉三块——余额与领取入口、三条承诺（事前可见预估 / 失败不扣 / 实际与预估差 ≤40%）、计费规则表 + 消耗明细流水。规则表按消耗从高到低排列（整体制作 ~40 → 方案改造 ~30 → 快速修改 ~8 → 视觉方向 ~5 → 体检 ~2），免费项（对话、直接改文字）归在最后。

实现仅在操作成功后记账；失败记一笔 cost: 0, status: "failed" 流水，明细中显示「失败 · 未扣除」。实际消耗按产出字符数在预估 ±40% 内浮动（scale = clamp(outputChars/30000, 0.6, 1.4)）。

验收任何会扣分的按钮附近可见预估；触发一次失败后明细出现未扣除记录且余额不变。

02进度与预估时长

交互制作页：预估剩余时间倒计时 + 阶段文案 + 本次预估消耗与"失败不扣"承诺；快速修改遮罩同样显示预估剩余时间。

实现进度条取「时间进度」与「生成字符数进度」较大者，封顶 96%。预估来源 aps.durations.v1：每类操作最近 5 次真实耗时取均值；无历史用默认值（build 90s / revise 75s / patch 35s / styles 20s / qa 15s）。

验收第二次同类操作的预估应接近第一次的真实耗时。

03失败可诊断、可恢复

交互构建 / 修改失败弹层——失败原因、保留的修改要求原文、「↻ 原样重试」、"未扣积分"明示。

实现Studio 内 BuildFailure 保存完整现场（mode / spec / style / baseHtml / instruction / element / label），重试即原参重跑。

验收失败后无需重新输入任何内容即可重试；失败不产生扣费流水。

04修改清单

交互编辑模式点选元素 → 输入修改要求 → 「＋加入清单」（可攒多处）→ 顶部清单条「一次改完 N 处（~8 积分）」。

实现多条指令拼成「修改点 1/2/3…」一次 patch 请求；ENGINEER_SYSTEM 增加约束：逐条执行、互不影响、严格按字面、不顺手重构。

验收N 处修改只产生一笔 patch 费用、一个新版本。

05产品体检

交互预览工具栏「🩺 体检」→ 报告面板（一句话总评 + 问题列表：严重程度 / 标题 / 大白话表现）→ 单条「修复」或「一键修复全部」（合并为一次 patch 计费）。

实现新接口 POST /api/qa（见第六节）；QA_SYSTEM 检查清单直接取自真实用户报障：文字重叠遮挡、点不动的按钮 / 红点、空壳入口、图表异常、JS 运行错误、乱码占位文案、手机适配。

验收对一个故意有重叠文字的 HTML 能报出问题并给出可执行修复指令。

06版本恢复

交互历史菜单每个旧版本行尾「⟲ 恢复」（把旧版推为新的最新版，免费，历史不丢）；查看旧版本时顶部黄色横幅「正在查看 vN（不是最新版本）· 恢复这个版本 / 回到最新」。

验收恢复后版本数 +1、标签为「恢复自 vN」；原最新版仍在历史里。

07需求输入增强

交互📎 附件支持 txt / md / csv / json（≤5 万字读入全文随消息发送，展示折叠为「📎 已附上《文件名》」）；PDF / Word / 图片选择后提示"识别支持中，请先粘贴文字"。附件全文包裹在 【附件：文件名】…【附件结束】 中进入对话上下文。

实现PM 提示词：参考材料 / 竞品要点提取并点明"参考了你提供的 XX"；批量需求先逐条编号复述（采纳 / 调整 / 暂不做）再出整体方案。

验收上传 md 文件后 PM 回复能引用文内要点；一次发 5 条需求能得到逐条回应。

08平台能力自动开通

协议PM 方案 JSON 新增 recommendedServices: [{id, reason}]（0~3 项，id 限 12 项平台能力）。

交互确认方案时自动开通（依赖联动：auth→cloud，collab→auth+cloud），toast 告知；方案卡能力行显示绿色「方案推荐」徽标 + 推荐原因。

验收方案提到"云端同步"时，确认后云端数据自动开启且显示原因；用户仍可手动关闭。

09发布：暂停访问

协议PublishState.status 增加 "paused"。

交互已上线产品的线上状态卡新增「⏸ 暂停访问」；暂停后状态徽标变黄「⏸ 已暂停访问」，文案说明"项目、数据、链接都保留"，可「▶ 恢复访问」。

验收暂停 / 恢复往返状态与文案一致；暂停不清除 url / liveVersion 等任何字段。

其他小项

  • 设计师提示词：三个视觉方向的说明需帮助选择（"适合谁 / 什么场合"）。
  • 工程师提示词：颜色 / 样式修改按字面精确执行（回应"调颜色多次解读出错"）。
  • 模型档位：设置里已有三档模型；计费规则文案写明"更强模型消耗更高"。

第六节

接口与数据结构变更

新增接口 POST /api/qa

// 请求
{ "html": "<!DOCTYPE html>…", "spec": { /* Spec */ }, "model": "claude-opus-4-8" }

// 响应（JSON Schema 强约束）
{
  "summary": "整体可用，有 2 处显示问题建议修复",
  "issues": [
    { "title": "…", "detail": "…", "severity": "high|medium|low", "fix": "给工程师的修复指令" }
  ]
}

鉴权与其余接口一致：x-aps-key 请求头可覆盖服务端 ANTHROPIC_API_KEY。

PM 方案 JSON 协议新增字段

"recommendedServices": [{ "id": "cloud", "reason": "换设备打开记录不丢" }]
// id 限定 12 项平台能力；0~3 项；前端 parseProposal 做容错清洗

localStorage 新增 key

key内容
aps.credits.v1{balance, entries[≤60]} 积分账本（全局，跨项目）
aps.durations.v1{kind: ms[≤5]} 各操作最近耗时

ProjectData 新增 demo?: boolean；旧项目数据无需迁移（字段缺省即非演示）。

  5. 体检叠加无头浏览器真实渲染检查
