# v0.2 版本说明（给研发团队）

> 本版本主题：把产品价值链从「做出来能看」延伸到「真正上线能用」。
> **交付物是产品原型**：所有新增交互完整可演示，发布/打包/平台服务的后端为 mock，
> 由研发按本文档与 `docs/shipping.md` 的方案接入真实实现。
> 商业化暂不做，所有能力按免费开放实现。

## 一、本版本更新了什么

### 1. 新增阶段⑤「发布上线」
- 步骤条从四步扩为五步；预览工具栏新增「🚀 发布上线」按钮（已上线时显示「● 已上线 · 管理发布」）。
- 新组件 `components/PublishPanel.tsx`，包含：
  - **五个产品出口**：Web 一键发布（mock 部署 → 生成 `app-{id}.zaowu.app` 链接）、H5（随 Web 上线 + 二维码，当前为伪二维码占位）、安卓 APK（mock 构建流程）、微信小程序（接入说明弹窗 + 意向登记，方案见 `docs/miniprogram.md`）、iOS（规划占位）。
  - **草稿与线上分离**：版本历史是草稿流，发布把当前版本推到线上；草稿领先线上时提示「更新线上版本」，支持回退线上版本。
  - **平台能力管理**：见下节。
  - **自有云入口**：腾讯云 / 阿里云 / Railway 三个 connector 占位 + 接入指引弹窗。

### 2. 平台能力：12 项，两组呈现
- 定义在 `lib/constants.ts` 的 `PLATFORM_SERVICES`（含 `group` 字段）：
  - **常用能力**（默认展开）：账号体系、云端数据、AI 能力（含模型选择）、文件与图片存储、访客表单收集。
  - **更多能力**（默认折叠，有已开项时自动展开并显示计数）：积分钱包、消息通知、访问权限、多人协作、分享传播、地图与位置、访问统计。
- **勾选入口与语义**（产品设计上反复确认过，请保持）：
  - 主入口在方案卡片（阶段①与迭代期方案更新弹层），文案引导"越早确定，产品结构越合理"；
  - 发布页保留完整开关：**晚开通弹确认并触发一次产品改造**（patch 构建集成能力），关闭提示"下次修改时移除"；
  - `PLATFORM_SIDE_SERVICES`（访问权限、访问统计）为平台侧承载：开关即生效，不触发改造，也不注入构建提示词；
  - 依赖联动：账号 → 云端数据；多人协作 → 账号 + 云端数据。
- 每项能力的原型行为与落地方向见 `docs/shipping.md` 的能力矩阵。

### 3. 步骤条支持回看导航
- 已完成/可达的步骤可点击回去（「③ 制作中」为瞬态阶段不可作为目标；制作中锁定导航）。
- 回到阶段①：展示**已确认方案**（新分支，之前只显示待确认方案或空状态），清单与平台能力可直接调整，提示"下次修改产品时生效"。
- **revise 语义**：已有成品时确认新方案，走在现有产品上改造（`mode: "revise"`），不再退回视觉阶段重做；回看阶段②重选视觉并确认，则用新视觉整体重做（版本标签「更换视觉方向」）。

### 4. 数据结构变更（`lib/types.ts` / `lib/projects.ts`）
- `Stage` 增加 `"publish"`。
- 新增 `ServicesState`（能力开关 + AI 模型）与 `PublishState`（线上状态、URL、线上版本指针、渠道状态机 `idle/working/done`、AI Key）。
- `ProjectData` 增加 `services` 与 `publish` 字段；`loadProjectData` 内置旧数据迁移（缺失字段自动补默认值），刷新自愈逻辑覆盖 publish 阶段。
- 新增 `publishSummary()`（工作台卡片上线徽标/访问量）与 `mockVisits()`（演示访问量：按上线时长匀速累计）。

### 5. 提示词与构建 API 变更（真实生效，非 mock）
- `lib/prompts.ts`：
  - PM 边界改为"平台能力可勾选接入"（12 类需求不再拒绝，引导勾选）；暂不支持项只剩真实收款、短信/微信通知；
  - 工程师系统提示词新增「平台服务本地模拟规范」——每项能力在单文件产品里如何做可交互的模拟（登录界面、base64 图片存储、表单收集入口、通知中心、成员列表、canvas 分享海报、Leaflet 地图带降级等），未开通的服务不得出现。
- `app/api/build/route.ts`：请求体新增 `services`，build/revise 模式注入已开通能力清单（patch 不注入，避免小修改引入大改动；平台侧服务始终不注入）。

### 6. 其他
- 工作台项目卡片显示上线状态徽标与访问量。
- 示例项目预勾常用组 5 项 + 积分钱包，便于演示。

## 三、后续开发建议与方案

详细架构与分期见 `docs/shipping.md`，这里是给研发的重点提示：

### 3.1 先补控制面（最重要的前置）
当前一切状态在浏览器 localStorage，没有平台账户。而"发布上线"天然要求服务端记录（发布记录、域名、能力开通、AI Key、用量）。**第一个工程动作应该是平台账户体系 + 项目云端化**，否则后面每个能力都没有挂靠点。迁移策略：登录后把 localStorage 项目上传合并，保留本地模式作离线兜底。

### 3.2 平台 SDK 隔离层（架构关键决策）
生成的产品不要直接对接各服务 API。注入稳定的极简 SDK（`sdk.auth.*` / `sdk.db.*` / `sdk.storage.*` / `sdk.ai.*` / `sdk.forms.*`），未发布时走本地模拟（行为对齐当前提示词规范），发布后指向真实服务。好处：生成器提示词不随服务实现变化；已发布产品可平滑升级；本地模拟与真实服务共用同一接口契约，原型行为即验收标准。

### 3.3 分期建议
1. **Phase 1 — 链接就是上线**：静态托管（对象存储 + CDN + 泛域名）、真实二维码、PWA、访问统计埋点。原型交互可直接复用，只替换 mock 的发布动作。
2. **Phase 2 — 云端底座**：平台 SDK、账号（OAuth 网关 + 每应用用户池）、云数据、文件存储、表单收集、AI 网关（scoped key、模型白名单、限流计量）。
3. **Phase 3 — 出口与生态**：APK 云构建（Capacitor/TWA）、小程序代提审（`miniprogram-ci`，见专项文档）、消息通知（先邮件 + Web Push）、访问权限、自有云 connector、积分服务端化、协作/分享/地图。

### 3.4 工程注意事项
- **安全**：用户自带 API Key 经 `x-aps-key` 头转发，服务端不落盘——上线版要加速率限制与日志脱敏；生成的单文件 HTML 在 sandbox iframe 预览，托管后是独立域名，注意与主站的 Cookie/存储隔离；AI 网关必须做每应用配额与滥用检测。
- **合规**：托管域名 ICP 备案是国内链路（小程序 web-view、微信分享）的最长前置，建议立刻启动；UGC + 公开访问的产品默认接内容审核（平台自动附带，不是用户选项）。
- **发布模型**：`PublishState.channels` 已是状态机（`idle/working/done`），接真实任务队列时补 `failed` 态与错误信息即可，前端结构不用动。
- **版本存储**：单文件 HTML 每版可达数百 KB，localStorage 有 12 版上限 + 超限裁剪逻辑；云端化后建议内容寻址去重。
- **积分钱包**：现阶段严格保持虚拟积分定位；真实收款涉及支付牌照/二清合规，方案定了再动（服务商模式）。

### 3.5 验收基准
原型即验收标准：研发接入真实服务后，用户可感知的流程、文案、状态流转应与当前 Demo 一致（体验过 Demo 的用户无需重新学习）。跑 Demo：`npm run dev`（端口注意避开 3000/3100），首页创建示例项目 → 「🚀 发布上线」走全流程，无需 API Key。
