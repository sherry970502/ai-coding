## 一、版本概述

**主题：透明、可控、能恢复。**

来源是 2026-10 的用户反馈收集表（47 条，9 位反馈人）。归纳后三大痛点高度集中：

| 痛点 | 反馈条数 | 典型原话 |
|---|---|---|
| 等待不透明 | 7 | "迭代等待时间太久""开发过程无反馈、无进度提示""建议给出预估等待时间" |
| 消耗不透明 | 5 | "构建失败 token 也被计入，很奇怪""改几个字也要走一次完整构建，双倍消耗" |
| 失败救不回 | 8 | "生成失败不知道原因只能重试""输入框内容没保存，还得重新输一遍" |

其余六类：版本回退不可见、需求输入弱（传文档/竞品参考/批量需求）、平台能力无引导、成品质量问题（13 条 UI 缺陷）、无下线入口、想选高阶模型。

**产品原则不变**：技术不可见、交互完整、mock 先行；本文第四节明确每一处 mock 与真实实现的边界。

## 三、功能详解与验收标准

### 1. 积分账本与计费透明
- **交互**：顶栏常驻「⚡ 余额」；点开抽屉见三块——余额与领取入口、三条承诺（事前可见预估 / 失败不扣 / 实际与预估差 ≤40%）、计费规则表 + 消耗明细流水。
- **规则表排序**：按消耗从高到低（整体制作 ~40 → 方案改造 ~30 → 快速修改 ~8 → 视觉方向 ~5 → 体检 ~2），免费项（对话、直接改文字）归在最后。
- **记账时机**：仅在操作**成功**后记账；失败记一笔 `cost: 0, status: "failed"` 的流水，在明细里显示「失败 · 未扣除」——让承诺可被验证。
- **实际消耗**：按产出字符数在预估值 ±40% 内浮动（`chargeCredits` 内 `scale = clamp(outputChars/30000, 0.6, 1.4)`）。
- **验收**：任何会扣分的按钮附近都能看到预估；触发一次失败后明细里出现未扣除记录且余额不变。

### 2. 进度与预估时长
- **制作页**（`BuildProgress`）：预估剩余时间倒计时 + 阶段文案 + 本次预估消耗与"失败不扣"承诺；进度条取「时间进度」与「生成字符数进度」较大者，封顶 96%。
- **快速修改遮罩**（`PatchOverlay`）：同样显示预估剩余时间。
- **预估来源**：`localStorage["aps.durations.v1"]` 记录每类操作最近 5 次真实耗时取均值；无历史用默认值（build 90s / revise 75s / patch 35s / styles 20s / qa 15s）。
- **验收**：第二次同类操作的预估应接近第一次的真实耗时。

### 3. 失败可诊断、可恢复
- **交互**：构建/修改失败弹层——失败原因、保留的修改要求原文、「↻ 原样重试」、"未扣积分"明示。
- **实现**：`Studio` 内 `BuildFailure` 结构保存完整现场（mode/spec/style/baseHtml/instruction/element/label），重试即原参重跑。
- **验收**：失败后无需重新输入任何内容即可重试；失败不产生扣费流水。

### 4. 修改清单
- **交互**：编辑模式点选元素 → 输入修改要求 → 「＋加入清单」（可攒多处）→ 顶部清单条「一次改完 N 处（~8 积分）」。
- **实现**：多条指令拼成「修改点 1/2/3…」一次 patch 请求；`ENGINEER_SYSTEM` 增加约束：逐条执行、互不影响、严格按字面、不顺手重构。
- **验收**：N 处修改只产生一笔 patch 费用、一个新版本。

### 5. 产品体检
- **交互**：预览工具栏「🩺 体检」→ 报告面板（一句话总评 + 问题列表：严重程度/标题/大白话表现）→ 单条「修复」或「一键修复全部」（合并为一次 patch 计费）。
- **实现**：新接口 `POST /api/qa`（见第六节）；`QA_SYSTEM` 检查清单直接取自真实用户报障类型：文字重叠遮挡、点不动的按钮/红点、空壳入口、图表异常、JS 运行错误、乱码占位文案、手机适配。
- **验收**：对一个故意有重叠文字的 HTML 能报出问题并给出可执行修复指令。

### 6. 版本恢复
- **交互**：历史菜单每个旧版本行尾「⟲ 恢复」（把旧版推为新的最新版，免费，历史不丢）；查看旧版本时顶部黄色横幅「正在查看 vN（不是最新版本）· 恢复这个版本 / 回到最新」。
- **验收**：恢复后版本数 +1、标签为「恢复自 vN」；原最新版仍在历史里。

### 7. 需求输入增强
- **附件**：📎 支持 txt/md/csv/json（≤5 万字直接读入全文，随消息发送；展示折叠为「📎 已附上《文件名》」）；PDF/Word/图片选择后提示"识别支持中，请先粘贴文字"。附件全文包裹在 `【附件：文件名】…【附件结束】` 中进入对话上下文。
- **PM 提示词**：参考材料/竞品要点提取并点明"参考了你提供的 XX"；批量需求先逐条编号复述（采纳/调整/暂不做）再出整体方案。
- **验收**：上传 md 文件后 PM 回复中能引用文内要点；一次发 5 条需求能得到逐条回应。

### 8. 平台能力自动开通
- **协议变更**：PM 方案 JSON 新增 `recommendedServices: [{id, reason}]`（0~3 项，id 限 12 项平台能力）。
- **交互**：确认方案时自动开通（含依赖联动：auth→cloud，collab→auth+cloud），toast 告知；方案卡能力行显示绿色「方案推荐」徽标 + 推荐原因。
- **验收**：方案提到"云端同步"时，确认后云端数据自动变为开启且显示原因；用户仍可手动关闭。

### 9. 发布：暂停访问
- **协议变更**：`PublishState.status` 增加 `"paused"`。
- **交互**：已上线产品的线上状态卡新增「⏸ 暂停访问」；暂停后状态徽标变黄「⏸ 已暂停访问」，文案说明"项目、数据、链接都保留"，可「▶ 恢复访问」。
- **验收**：暂停/恢复往返状态与文案一致；暂停不清除 url/liveVersion 等任何字段。

### 其他小项
- 设计师提示词：三个视觉方向的说明需帮助选择（"适合谁/什么场合"）。
- 工程师提示词：颜色/样式修改按字面精确执行（回应"调颜色多次解读出错"）。
- 模型档位：设置里已有三档模型；计费规则文案写明"更强模型消耗更高"。

## 四、Mock 与真实实现边界（研发重点）

| 模块 | 当前 mock 实现 | 真实实现要点 |
|---|---|---|
| 积分账本 | `localStorage["aps.credits.v1"]`，初始 500，前端记账 | 后端按真实 token 结算；前端只展示。**规则数值（40/30/8/5/2）需按真实模型成本标定**；「±40%」承诺需按真实数据回测 |
| 预估时长 | 本机最近 5 次耗时均值 | 服务端按需求规模（prompt 长度、模块数）给预估，跨设备一致 |
| 失败重试 | 整次原参重跑 | 断点续作：服务端保存生成现场，从中断 token 处续写（v0.4 核心，直接回应"中断后重复消耗"） |
| 产品体检 | 模型静态读 HTML | 可叠加无头浏览器跑真实渲染快照 + 控制台错误采集 |
| 附件 | 纯文本直接进上下文 | 文档解析服务（PDF/Word/OCR）+ 超长文档后端摘要 |
| 暂停访问 | 前端状态字段 | 网关层访问开关 + 暂停提示页；工作台仪表盘对 paused 项目目前按未上线展示，需补状态徽标 |
| 发布/打包/小程序 | v0.2 既有 mock，未变 | 见 `docs/shipping.md`、`docs/miniprogram.md` |
| 演示模式 | `ProjectData.demo = true` 的项目，对话/制作/修改/体检全部本地模拟（见第七节） | 上线后保留，作为新用户零成本试玩通道 |

**明确不做**（已对用户说明）：小程序真机预览（微信审核机制限制，反馈表备注已确认无解）。

## 六、接口与数据结构变更

### 新增接口 `POST /api/qa`
```jsonc
// 请求
{ "html": "<!DOCTYPE html>…", "spec": { /* Spec */ }, "model": "claude-opus-4-8" }
// 响应（JSON Schema 强约束）
{
  "summary": "整体可用，有 2 处显示问题建议修复",
  "issues": [
    { "title": "…", "detail": "…", "severity": "high|medium|low", "fix": "给工程师的修复指令" }
  ]
}
```
鉴权与其余接口一致：`x-aps-key` 请求头可覆盖服务端 `ANTHROPIC_API_KEY`。

### PM 方案 JSON 协议新增字段
```jsonc
"recommendedServices": [{ "id": "cloud", "reason": "换设备打开记录不丢" }]
// id 限定 12 项平台能力；0~3 项；前端 parseProposal 做容错清洗
```

### localStorage 新增 key
| key | 内容 |
|---|---|
| `aps.credits.v1` | `{balance, entries[≤60]}` 积分账本（全局，跨项目） |
| `aps.durations.v1` | `{kind: ms[≤5]}` 各操作最近耗时 |

`ProjectData` 新增 `demo?: boolean`；旧项目数据无需迁移（字段缺省即非演示）。

## 七、演示模式（无需 API Key 的完整试玩通道）

入口：新建项目 → 「▶ 先看一个演示成品」。载入后 `demo: true` 持久化，刷新保持。

| 环节 | 模拟行为 |
|---|---|
| 对话 | 产品经理流式回复（附件消息会点明已读取文件名） |
| 制作/修改 | 本地模拟进度（整体 6s / 快改 3.8s），完成后在成品底部盖「✔ 演示修改已应用：{label}」回执条（重复修改替换不叠加），照常记账 |
| 失败恢复 | 修改要求含「失败」二字 → 第一次模拟中断（弹层 + 不扣费流水），重试即成功 |
| 体检 | 1.6s 后返回预置报告 `DEMO_QA` |
| 预置数据 | 3 个历史版本（试「恢复」）、种子积分流水（含一笔「失败 · 未扣除」）、方案卡预置 2 项「方案推荐」能力 |

## 八、验证情况与已知限制

**已验证**：`tsc --noEmit`、`next build` 通过；本地 `next start` 冒烟（首页/项目页 200，`/api/qa` 链路通，错误路径文案可读）；演示模式全流程手测路线见上节。

**未验证**：真实 API 生成链路（开发机凭证仅允许 Claude Code 客户端，503）。**请在配置正常 `ANTHROPIC_API_KEY` 的环境回归**：PM 对话出方案（含 recommendedServices）、体检真实报告质量、多修改点合并执行的准确率。

**已知限制 / 建议 v0.4**：
1. 断点续作（失败重试 = 整次重跑，后端保存生成现场后可从中断处续写）——用户痛点原文"中断后无法继续且重复消耗 tokens"；
2. 积分规则数值需按真实 token 成本标定；
3. 工作台仪表盘未显示 paused 状态徽标；
4. PDF/Word/图片附件解析；
5. 体检叠加无头浏览器真实渲染检查；
6. 多处修改合并后单点失败的部分成功处理（当前一损俱损）。
