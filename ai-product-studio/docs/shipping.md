# 发布上线能力 · 研发交接说明

> 本文档配合产品原型（阶段⑤「发布上线」）阅读。原型已完整呈现目标交互，
> 本文标注每个模块**当前是 mock 还是真实实现**，以及落地时的技术方向。
> 商业化（付费）暂不做，所有能力先按免费开放实现。

## 总体设计

价值链从「做出来能看」延伸到「真正上线能用」。核心设计原则：

1. **技术对用户不可见**：不问"要不要数据库"，只问"想怎么用它"。
2. **渐进升档**：本地文件 → 在线链接 → 云端应用（账号/数据/AI）→ 装到手机/上架商店。每一档是升级不是分叉，用户随时可升档、不推倒重来。
3. **Web-first 一套底座**：生成器始终产出 Web 应用；APK / 小程序 / iOS 是同一底座的「打包出口」，不维护多条代码生成管线。
4. **草稿与线上分离**：现有的版本历史是草稿流；「发布」把某个版本推到线上，之后可继续迭代草稿、一键更新或回滚线上版。

## 模块与实现状态

### 1. Web 一键发布（原型：mock）
- 现状：点击「🚀 一键发布」→ 模拟 2~3 秒部署 → 生成 `https://app-{id}.zaowu.app` 假链接，状态存 localStorage（`PublishState`，见 `lib/types.ts`）。
- 落地方向：成品是自包含单文件 HTML，发布即静态托管——对象存储 + CDN + 泛域名（`*.zaowu.app`）即可，不需要为每个用户产品跑服务。需要真实的项目云端账户体系承载发布记录。
- 待做：自定义域名绑定、访问统计（原型中访问量按上线时长匀速 mock，见 `lib/projects.ts` 的 `mockVisits`）。

### 2. H5（原型：真实逻辑的一部分）
- H5 = 同一链接的移动端适配（生成器已强制响应式），发布 Web 后自动可用。
- 原型中的二维码是**伪二维码**（`PublishPanel.tsx` 的 `PseudoQr`，仅视觉占位），落地时换成真实链接的 QR 生成 + PWA manifest 注入（支持"添加到主屏幕"）。

### 3. 安卓 APK（原型：mock）
- 现状：「📦 打包安装包」→ 模拟 2.6 秒构建 → 展示假文件名。
- 落地方向：云端构建服务，用 Capacitor/TWA 把 Web 底座打成 WebView 壳 APK，签名后提供下载。用户侧零操作。

### 4. 微信小程序（原型：入口 + 流程说明）
- 见 `docs/miniprogram.md` 专项说明。原型中提供渠道卡片入口和四步接入说明弹窗，「我有兴趣，通知我」用于收集意向。

### 5. iOS（规划中占位）
- 渠道卡片仅展示规划：需 Apple 开发者账号、打包（Capacitor）、App Store 提审代办清单。优先级最低。

### 6. 平台服务（原型：勾选交互真实，服务本身 mock）
**能力决策以需求阶段为主，全程可调整**：主入口在方案卡片（SpecCard，阶段①出方案与迭代期方案更新弹层均有）——能力影响产品架构，越早确定改造成本越低，文案向用户传达这一点。发布阶段（PublishPanel）保留完整开关：**晚开通会弹确认并触发一次产品改造**（patch 构建把能力集成进现有产品，改完回到迭代页产生新草稿），显性传达"晚开能力有改造成本"；关闭则提示"下次修改产品时移除"；访问统计例外（平台侧承载，开关即生效，不动产品）。勾选状态存 `ServicesState`：

能力分两组呈现（原型中 SpecCard 与 PublishPanel 均按此分组）：**常用能力**默认展开（账号、云端数据、AI、文件存储、表单收集），**更多能力**折叠（钱包、通知、权限、协作、分享、地图、统计；组内有已开项时默认展开，标题显示已开数量）。入选标准：小白高频需要 × 必须平台侧提供基础设施 × 勾选影响产品结构。内容审核、数据备份不做勾选项——前者平台默认自动附带（合规责任不转嫁给用户），后者是默认信任承诺。

| 服务 | 组 | 原型行为 | 落地方向 |
|---|---|---|---|
| 账号体系 | 常用 | 勾选后生成的产品带模拟登录界面（微信/Google/手机号，点击即"登录成功"） | 平台 OAuth 网关 + 每应用的用户池 |
| 云端数据 | 常用 | 产品内显示"已同步"标识，实际仍 localStorage；勾选账号时自动联动开启 | BaaS 数据服务，SDK 接口对齐 localStorage 语义降低生成器负担 |
| AI 能力 | 常用 | 发布时签发假 Key（`aps_live_*`）；生成的产品用预置示例响应模拟，标注"AI 演示响应" | 平台 AI 网关：每应用 scoped key、模型白名单、限流计量；用户选模型或"交给系统" |
| 文件与图片存储 | 常用 | 图片上传用 FileReader→base64 存本地，标注"已同步到云端存储"；发布页显示 mock 用量 | 对象存储 + 每应用配额；补齐"云端数据"只能存文字的缺口 |
| 访客表单收集 | 常用 | 表单提交存本地并提示"将同步到你的后台"；发布页显示 mock 提交数 | 免登录提交端点 + 汇总后台/邮件投递；注意与"云端数据"的心智区分（访客的数据 vs 使用者自己的数据） |
| 积分钱包 | 更多 | 生成的产品内置完整本地积分体系（余额/明细/获取规则） | 先虚拟积分服务端化；真实收款走服务商模式（支付合规硬门槛，远期） |
| 消息通知 | 更多 | 产品内通知中心模拟，触发时显示"已通过邮件/推送通知" | 首期邮件 + Web Push；短信/微信模板消息需资质与模板审核，后置 |
| 访问权限 | 更多 | 发布页显示 公开/密码/仅邀请 状态 chips（演示）；平台侧承载，开关即生效、不改造产品 | 托管层访问校验：私密链接、密码、邀请制、"仅登录用户可用"（配合账号体系） |
| 多人协作 | 更多 | 生成的产品模拟成员列表与"共享空间"标识；勾选自动联动开启账号+云端数据 | 账号+云数据之上的共享空间与数据权限模型，二期 |
| 分享传播 | 更多 | 生成的产品带 canvas 分享海报 + 复制链接 | 海报模板服务、OG 卡片、短链 + 渠道归因统计 |
| 地图与位置 | 更多 | 生成的产品可用 CDN 地图库（Leaflet），断网降级文字地址 | 腾讯/高德统一接入（国内合规），平台侧 Key 管理 |
| 访问统计 | 更多 | 上线后显示 mock 访问量（标注"演示数据"）；平台侧承载，开关即生效 | 托管侧埋点即可 |

**关键工程设计（建议）**：生成的产品不直接对接各服务 API，而是注入一个稳定的平台 SDK（`sdk.auth.login()` / `sdk.db.save()` / `sdk.ai.chat()` 级别的极简接口）。未发布时 SDK 走本地模拟，发布后指向真实服务。生成器提示词只需声明"哪些能力可用"，不随服务实现变化。

### 7. 外接自有云（原型：入口 + 指引弹窗）
- 腾讯云 / 阿里云 / Railway 三个入口，弹窗展示"获取密钥 → 粘贴连接 → 随时搬家"三步。
- 定位：打消锁定顾虑的进阶能力，承诺先行（数据可导出、可迁移），实现后置。落地为各云的部署 connector（用户粘贴最小权限 Token，平台代部署）。

### 8. 生成器提示词变更（已生效，非 mock）
- `lib/prompts.ts`：PM 边界从"不支持账号/支付"改为"通过平台服务开通"；工程师系统提示词新增「平台服务本地模拟」规范。
- `app/api/build/route.ts`：构建请求携带 `services`，生成/改版时注入已开通服务清单（patch 模式不注入，避免小修改引入大改动）。

## 建议落地顺序

1. **Phase 1 — 链接就是上线**：真实静态托管 + 泛域名 + 真 QR + PWA。原型交互可直接复用，只换掉 mock 的发布动作。
2. **Phase 2 — 云端底座**：平台 SDK + 账号 + 云数据 + AI 网关（含 Key 签发与计量）。
3. **Phase 3 — 出口与生态**：APK 云构建、小程序代提审、自有云 connector、积分服务端化。
